# المناهج والدروس (روايات · مانجا · فيديو)

هذا ملف مرجع للمولّد وللمطوّر: ما جرّبناه، وما فشل، وكيف حُلّ.

## قواعد عامة للمولّد
1. يكفي رابط الموقع. يجد عملاً وفصلاً/حلقة نموذجية بنفسه، ويسأل المستخدم فقط عمّا عجز عنه.
2. **التحقق قبل الاعتماد:** نقارن العدد المجلوب بالمعلن في الصفحة (فصول) أو نتأكد أن الرابط يشتغل فعلاً (فيديو).
3. **سباق الاستراتيجيات:** نجرّب عدة طرق ونختار الأكمل، لا الأولى التي تُرجع شيئاً.
4. **استبدال آمن:** البديل يُقارن بالأصلي على العمل نفسه، ولا يُقبل إلا إن بلغ ≥ 95% من الأصلي.
5. **تحليل السرعة:** قياس الحالية ثم البدائل، وعرض «أسرع / مماثلة / ناقصة» مع زر استبدال بلا تحديث للتطبيق.
6. **النطاقات تتبدّل:** تعديل الرابط يدوياً مع نقل المكتبة والتقدّم والتنزيلات تلقائياً، ومرايا احتياطية.

## الروايات
- قوالب: Madara، MangaStream/Themesia، generic، api، وبعض المحرّكات الخاصة (kolnovel، novltime، riwayatarab، seanovel، sunovels).
- **قائمة جزئية (24 من 1505):** صفحة العمل تعرض آخر الفصول فقط. الحل: سباق بالعدد المعلن، وإكمال Madara عبر ajax، وملء الأرقام (numeric fill) حين تكون الروابط متسلسلة.
- **فجوات الترقيم (5201 مقابل 5184):** نخفي الفصل غير الموجود عند 404.
- **نص الفصل:** مرشّح شامل للإعلانات وعبارات الواجهة وأسطر «الحماية من النسخ»، مع قواعد خاصة بالموقع (rules.json، 765 موقعاً).
- **مواقع JSON:** قالب `api` يُوصَف بالبيانات (known.json): قائمة، بحث، فصول مقسّمة لصفحات أو نقطة «كل الفصول»، نص الفصل.
- **وردبريس:** احتياطي wp-json حين تفشل الصفحة.
- **التقاط الشبكة** لزر «عرض المزيد» حين لا يظهر الرابط في HTML.

## المانجا
- قوالب: Madara (+ ajax، صفحات، فصول الصفحة)، MangaStream/Themesia، ZeistManga (Blogger)، Iken/Azora (API).
- كشف Iken: `api.<النطاق>/api/query` أو `<النطاق>/api/query` ويحمل `posts[].slug`.
- مصدر مخصص: المحوّل الخاص يغلب القالب؛ لذلك الاستبدال يتطلب علم `ovr` يتجاوز المحوّل واستثناءات الموقع.
- tRPC (MangaTime) وواجهات JSON (FlixScans) ضمن المحوّلات الخاصة.

## الفيديو (انظر knowledge/video)
- طبقات بالترتيب: API ← قالب معروف مع مستخرج الخادم ← التقاط الشبكة؛ ومعها حلّ Cloudflare عند الحاجة.
- مفتاح المطابقة بين المصادر: tmdb_id. العقد الموحّد: `getStreams(tmdbId, mediaType, season, episode)`.
- الخوادم تُطابَق بالاسم الأساسي (streamwish له عشرات النطاقات المتبدّلة).
- روابط HLS قد تكون مربوطة بالـIP فتُشغَّل من جهاز المستخدم.

## الزحف الكامل للكتالوج (درس novltime، Next.js)
المشكلة: الصفحات الثابتة تعرض 24–48 عملاً فقط، والباقي عبر «عرض المزيد» (متصفح مخفي: بطيء وهش).
الطريقة المعتمدة للمولّد حين يُعطى رابط الموقع فقط، بالترتيب:
1. **ابحث عن API القائمة بدل الصفحات:** افتح صفحة الاستكشاف في متصفح فيه DevTools وراقب طلبات Fetch/XHR أثناء «عرض المزيد»؛ الطلب المطلوب شكله `/api/.../search?...&cursor=...`. (الموقع الذي يمنع robots لا يُجلب بـWebFetch؛ التطبيق نفسه يطلبه مباشرة فلا مشكلة.)
2. **المؤشر (cursor):** نص طويل يبدأ غالباً بـ`eyJ` (base64 لـJSON). نكتشفه عامّاً: أي نص يبدأ `eyJ` وطوله ≥ 30 في الرد. الصفحة التالية = نفس الطلب + `cursor=` الأخير. لا نفترض اسم الحقل.
3. **أسماء الترتيب تُكتشف لا تُخمَّن:** قد يرفض الخادم `latest` بـ400 بينما يقبل `newest`. نجرّب `[latest, updated, recent, newest, new, updatedAt, createdAt, date]` ونحفظ المقبول، ونسجّل جسم الخطأ.
4. **حقول العنصر:** `title`, `slug`, `genres`, الغلاف في حقل غير معروف → نفحص القيم بحثاً عن `/uploads/` أو امتداد صورة، ونفكّ روابط `/_next/image?url=`.
5. **فهرس محلي للبحث:** كل ما يُجلب يُضاف إلى فهرس عناوين محلي (24 ساعة)، والبحث يبدأ منه ثم الموقع.
6. **احتياطات تأتي بعد API:** صفحات التصنيفات `/genre/<g>`، ثم `feed.xml`، ثم sitemap (غالباً بلا روابط أعمال)، ثم المتصفح المخفي.
7. **فصول الأعمال الطويلة:** الصفحة تعرض أول ~120 فصلاً مع العدد الكلي، فنكمل بملء الأرقام (`chapter-N`) حتى العدد المعلن.
- نتيجة: 1240 من 1273 عملاً بأغلفتها في ~65 طلباً (~0.5 ثانية للطلب)، مقابل 44 قبل ذلك.
- تحذير WebView: المتصفح المخفي يجب أن يبقى منه شريط 2px ظاهراً وإلا توقف العرض (Android off-screen throttling).

## واجهة وردبريس التطبيقية (درس kolnovel)
- `wp-json/app/v2/{reading-list,titles,discover,reader/<id>}` عامة في بعض مواقع kolnovel؛ `reader` يُرجع `has_access` (مغلق إن كان false).
- جلب صفحات القائمة بالتوازي (3 صفحات مسبقاً) يخفّض 1300 فصل من دقائق إلى ~17 ثانية.

## دليل الاستطلاع: الأدلة قبل التخمين (للمولّد)
المبدأ: كل طلب مُخمَّن مكلف (الخيوط الأصلية 6 فقط) وأغلبه 404. نجمع الأدلة من الموقع نفسه أولاً، ثم نخمّن بميزانية صغيرة.
| الدليل | أين يُرى | ماذا نستنتج |
|---|---|---|
| وردبريس | `/wp-json/` فيه `namespaces`+`routes` أو `<link rel="https://api.w.org/">` | نقرأ مسارات chapter/reading/search/discover من الفهرس (مثل `app/v2` في kolnovel) بدل تخمينها؛ قد يكون الفهرس 403 والمسارات مفتوحة |
| مسارات API في الشيفرة | نصوص `"/api/..."` و`https://api.*` داخل سكربتات الصفحة وأول 4 حزم JS | تُقدَّم كبادئات أولى للتخمين، وتُرفع الميزانية من 60 إلى 420 طلباً |
| Next RSC | `self.__next_f.push` بلا `__NEXT_DATA__` ولا مسارات api | الموقع مرسوم من الخادم: نحلّل HTML فقط ولا نخمّن API (riwayatarab) |
| Next (pages) | `__NEXT_DATA__` + `/_next/data/<buildId>/…json` | بيانات الصفحة JSON جاهزة |
| Nuxt | `__NUXT__`, `/_nuxt/`, `_payload.json` | الحمولة تحوي القوائم |
| نموذج البحث | `form[role=search]` أو `input[name=s|q|query|keyword|…]` + الحقول المخفية | رابط البحث يُبنى من النموذج (kolnovel: `?s=&post_type=series`) |
| OpenSearch | `<link rel="search" type="application/opensearchdescription+xml">` | القالب `{searchTerms}` جاهز |
| حدود الترتيب | `hasMore=false` مبكراً في sort الشعبية | نكمل بترتيب آخر يغطي الكل ونحذف المكرر (novltime: popular 687 من 1273، newest كله) |
قاعدة إيقاف: بلا أدلة وتخمين 60 طلباً فاشلاً → نتوقف ونكمل بتحليل HTML. التنفيذ: `NovelApiDisc.scout` (www/sources/apidisc.js) و`declaredSearch` (www/sources/search.js).
